Dynamic Workflows (DW) 실행 엔진

Anthropic이 2026.05.28 Opus 4.8과 함께 발표한 병렬 서브에이전트 오케스트레이션 엔진.

  • Claude가 JS 오케스트레이션 스크립트 작성
  • 런타임이 백그라운드에서 스크립트 실행
  • 병렬 서브에이전트 동시 16 / 누적 1,000개
  • 중간 결과를 스크립트 변수에 격리 → 컨텍스트 절약
  • 실증: Bun 75만 줄 코드베이스 11일 처리
핵심 전제 — 층위가 다르다

백호 특허와 DW는 경쟁 기술이 아니다. 백호 특허는 설계 방법론/인지 골격(소프트웨어 위 레이어), DW는 실행 엔진(런타임 레이어). "DW가 나오면 백호 특허가 쓸모없어지는가?"라는 질문 자체가 잘못된 전제다. 백호 특허는 DW를 포병 부대로 병과에 편입할 수 있다.

장단점

백호(白虎) 특허(출원 10-2026-0041235)

강점
  • 계층 분산 — 3층 편제(소대장-분대장-분대원)로 통신 O(n²)→O(n), 인지 부하·컨텍스트 오버헤드 감소
  • 인간 통제 게이트 — 임무 부여·작전 개시·해산 3회 게이트로 구조적 인간 통제, 작전 중 즉시 개입 가능
  • 이종 교차 검증 — Codex/Gemini/Grok/Perplexity 이종 외부AI 공유 풀로 동종 편향을 구조적으로 차단
  • DW 부대 흡수 — DW를 포병 부대로 병과 편입, 제병협동 지휘 체계 구성
  • 모델 등급 차등 — Opus/Sonnet/Haiku 차등 배치 × 작업량 분산으로 곱셈형 비용 절감
단점
  • 편제 설계 필요 — 분대 구성·병과 배치를 사전에 설계해야 하며 운용 진입 장벽이 있다
  • 분대장(Sonnet) 한계 — Sonnet 분대장이 복잡한 위임 판단에서 한계를 보일 수 있다 (Opus 대비)
  • 조율 토큰 오버헤드 — 계층 간 통신 메시지가 추가 토큰을 소비 (의도 정합성 보험료 성격)
  • 실측 벤치마크 수집 중 — 동일 작업 비용·품질 실측 데이터가 아직 부족

Dynamic Workflows

강점
  • 대규모 병렬 — 동시 16 / 누적 1,000 서브에이전트로 대량 화력 처리
  • 결정론적 재현 — JS 오케스트레이션 스크립트 기반이라 동일 입력에 동일 실행 경로 재현
  • 플랫폼 네이티브 — Claude Code 런타임에 내장된 실행 엔진, 변수 격리로 컨텍스트 절약
단점
  • 동종 검증 — Claude 단일 모델 패밀리 병렬 검증이라 동일 착각을 공유할 편향 위험 ("거울 앞에서 자기 얼굴 검증")
  • 인간 개입 약함 — 스크립트 자동 실행 중 인간이 방향을 바꾸기 어렵고 구조적 게이트가 없다
  • 복합 도메인 한계 — 다전문성·예외 판단이 섞인 작업보다 동종 대규모 병렬에 적합

3 · 약점 토론 6선 — 반박 결산

오늘(2026-05-30) 백호 특허 약점에 대한 심층 검토. 전항목 반박 우세로 결론.

약점 1 · 조율 토큰 비용 과다 반박 우세
약점 주장
소대장-분대장 간 통신 메시지가 추가 토큰을 소비한다.
반박
의도 정합성(misalignment) 방지 비용으로 정당화된다. 분대원 수백 개가 엉뚱한 방향으로 달리다가 재작업하는 비용이 훨씬 크다. 조율 토큰은 "보험료"다.
결론
약점이 아닌 의도적 설계 선택
약점 2 · 결정론·재현성 부족 반박 우세
약점 주장
소대장-분대장 간 "의사소통"이 비결정론적이라 같은 임무도 다른 결과를 낸다.
반박
융통성 자체가 강점이다. 코드 마이그레이션처럼 완전히 정의 가능한 작업은 DW가 낫지만, 설계 판단·복합 도메인·예외 처리가 섞인 작업은 결정론보다 적응 능력이 더 중요하다. 공식화 가능한 절차는 스킬로 정립하면 된다.
결론
작업 유형에 따른 적합성 차이일 뿐, 구조적 약점 아님
약점 3 · 작전 중 개입 불가 반박 우세
약점 주장
분대원이 작업 중 블로커를 만났을 때 소대장이 즉각 개입하기 어렵다.
반박
"게이트 3회" 원칙은 불필요한 개입 최소화 원칙이지, 긴급 개입을 금지하는 규정이 아니다. 소대장은 언제든 SendMessage로 개입 가능하다. DW는 스크립트 실행 중 인간이 방향을 바꾸기 더 어렵다.
결론
원칙≠금지, 오히려 백호 특허가 DW보다 인간 개입이 유연함
약점 4 · 의존 작업 컨텍스트 병목 반박 우세
약점 주장
A→B→C 순차 의존하는 작업에서 분대 간 인계가 병목이 된다.
반박
수평 교신(청구항 8)으로 분대장 간 직접 데이터 공유가 가능하다. 소대장을 경유하지 않고 Alpha→Bravo 직접 결과 전달. 컨텍스트도 분대별로 격리되어 오히려 소대장 컨텍스트 병목이 없다.
결론
수평 교신(청구항 8) + 컨텍스트 분산으로 해결됨
약점 5 · 플랫폼 의존성 및 실측 데이터 부족 일부 인정 (실측 한계)
약점 주장
Claude Code 전용이며 실제 성능 벤치마크가 없다.
반박
플랫폼 의존성: DW도 Anthropic 전용이다. 공평한 비교 불가. 반박 우세.
실측 데이터: "약점"이 아니라 "수집 중인 한계점"이다. 존재하지 않는 데이터를 약점으로 삼는 것은 논리 오류. 단, 데이터 수집 계획은 필요하다.
결론
플랫폼 반박 우세 / 실측은 "현재 한계" — 약점 분류 제외 적절
약점 6 · 적대적 검증 부재 역전 — 백호 특허 강점으로 전환
약점 주장
분대원이 같은 Claude 모델이라 같은 오류를 공유할 수 있다.
반박 (역전)
이것이 오히려 DW의 약점이다. 백호 특허는 이종 외부AI 공유 풀(Codex/Gemini/Grok/Perplexity)로 적대적 교차 검증이 구조적으로 내장되어 있다. DW의 동종 검증은 "거울 앞에서 자기 얼굴을 검증하는 것"이다.
결론
역전 — 백호 특허의 구조적 강점, DW의 구조적 약점

5 · DW 부대 설계 — 백호 특허가 DW를 병과로 흡수

5.1 실증 결과 (2026-05-30)

❌
경로 1 — 팀메이트가 Workflow 도구 직접 보유: 실패
팀메이트·서브에이전트 자리엔 Workflow 도구가 주입되지 않음. ToolSearch select:Workflow → No matching deferred tools found. Claude Code는 Workflow 도구를 최상위 세션에만 제공 (재귀 스폰 방지 설계).
✅
경로 2 — 분대장이 Bash로 헤드리스 claude -p 띄워 DW 가동: 성공
헤드리스 세션은 Opus 4.8 + Workflow 도구를 top-level 도구로 이미 보유 (ToolSearch 로드 불필요). 핵심은 "Workflow 도구를 DIRECTLY 호출하라"고 명시하는 것.

실증 Run IDs:
wf_01d2c4b1-5ae — agent_count 확인, subagent_tokens=42883
wf_5807cf0e-36e — agent_count 1, subagent_tokens 38624, 답 111을 PowerShell로 독립 재현 일치
핵심: 헤드리스 claude -p 세션에선 Workflow 도구가 이미 top-level 도구로 주입된다. ToolSearch로 로드할 필요 없음. 핵심은 "Workflow 도구를 DIRECTLY 호출하라"고 명시하는 것. "Run a workflow..." 자연어 키워드는 가짜 처리될 수 있으므로 사용 금지.

5.2 DW 부대 개념 — "포병 특수부대"

DW 부대는 Alpha/Bravo/Charlie 등 NATO 호출부호 순번과 무관한 특수부대다. NATO 호출부호 대신 DW-1, DW-2…로 호칭하며, Phase 1.5에서 일반 분대 수와 함께 편성 여부·수를 결정한다. 부대장은 Opus 4.8 이상 필수(헤드리스 세션이 Workflow 도구를 쥐어야 하므로).

ℹ️
플랜 요건: Dynamic Workflows는 Claude Max · Team · Enterprise 플랜에서만 가동된다. Pro 플랜은 미지원(Anthropic 공식) — Pro 이하 환경에서는 DW 부대를 편성하지 않고 일반 분대로 처리한다.
일반 분대 (NATO 호출부호 — Alpha, Bravo, Charlie…)DW 부대 (NATO 무관 특수부대)
병과 비유 보병 (정밀·기동) 포병 (대량 화력)
지휘 방식 분대장이 분대원에 위임 분대장이 직접 포 가동
부하 분대원 12명 (서브에이전트) DW 엔진 (동시 16, 총 1,000)

소대장 부담 낮음 낮음 — 포격은 분대장 별도 진지에서 전담

5.3 소대장 컨텍스트 무손상 원칙 (청구항 12)

DW를 소대장이 직접 가동하면 수십~수백 에이전트의 출력이 소대장 컨텍스트로 유입되어 지휘 능력이 저하된다. 소대장이 포를 쏘면서 어떻게 지휘하겠는가.

백호 특허의 해결: DW 부대장이 별도 헤드리스 프로세스에서 DW를 전담하고, 소대장에는 결과 요약만 보고된다. 소대장 컨텍스트 무손상. 이것이 기본 DW(소대장 직접 호출)보다 우월한 지점이다.

5.4 DW 부대 가동 절차

  1. 소대장이 판단: "DW형 작업"이라 판단 — 대규모 단일 의존 / 코드베이스 마이그레이션 / 완전그래프형 의존
  2. DW 부대장에게 위임: 소대장이 SendMessage로 DW 부대장에게 임무 전달
  3. DW 부대장이 Bash로 헤드리스 claude 기동: 
    claude -p --output-format json \
  "CALL the Workflow tool DIRECTLY with a script that {임무}.
   Report agent_count from the result." 2>&1
    ⚠️
    헤드리스 세션에서 Workflow 도구는 이미 top-level 도구 — ToolSearch 로드 불필요.
    "Run a workflow..." 자연어 키워드는 가짜 처리될 수 있음 — Workflow 도구 직접 호출을 명시해야 진짜 DW 발동.
  4. 진짜 DW 발동: 헤드리스 세션(Opus 4.8)에서 병렬 에이전트 처리 → stdout에 결과 반환
  5. 결과 수령 → 소대장 보고: DW 부대장이 결과 요약 → 소대장 컨텍스트 무손상
  6. 교차 검증: 용병(이종 외부AI)으로 결과 교차 검증 후 채택

5.5 DW 투입 기준 (소대장 판단)

  • 대규모 단일 상호의존 작업 (코드베이스 마이그레이션, 수백 파일 일괄 변환)
  • 단일 공유 메모리가 유리한 완전그래프형 의존
  • 다각도 교차 검증 리서치 (/deep-research)
"고비용 특수부대" 원칙

DW 부대는 수십~수백 에이전트라 토큰 소비가 크다. 포병을 함부로 쓰지 않듯, 대량 화력이 정말 필요한 작전에만 신중 투입. (백호 특허 모델 차등 철학과 일치)

6.1 관계 정의 — 백호 특허 ⊃ DW

백호 특허와 DW는 경쟁 관계가 아니다. 백호 특허가 DW를 병과로 흡수한다.

백호(白虎) 특허(출원 10-2026-0041235) — 설계 방법론/인지 골격
├── 보병 분대: Alpha, Bravo, Charlie, Delta, Echo (NATO 호출부호)
│ 각 분대원 12명 (Haiku/Sonnet)
├── DW 부대: DW-1, DW-2… (NATO 무관 특수부대 — Phase 1.5에서 편성 결정)
│ 부대장(Opus 4.8)이 헤드리스 claude -p로 Workflow 도구 직접 호출 → DW 엔진 가동
│ 동시 16 / 총 1,000 에이전트 화력 (Max·Team·Enterprise 플랜)
└── 특수정찰: 용병 공유 풀
Codex, Gemini, Grok, Perplexity (이종 교차 검증)

이것이 제병협동(諸兵協同) 지휘 체계다: 보병(분대) + 포병(DW 부대) + 특수정찰(용병).

DW 부대 설계 요지 (백호 특허에 편입된 결론적 설계)
  • 편성 — NATO 호출부호 없는 특수부대(DW-1, DW-2…). Phase 1.5에서 일반 분대 수와 함께 편성 여부·수를 결정.
  • 가동 — 부대장(Opus 4.8 이상)이 Bash로 헤드리스 claude -p 세션을 띄워 그 안에서 Workflow 도구를 직접 호출(키워드 아님). 헤드리스 세션은 Workflow가 이미 top-level 도구.
  • 소대장 무손상 — 포격은 부대장의 별도 진지에서 전담, 소대장엔 결과 요약만 보고 (청구항 12).
  • 검증 — DW의 동종 결과를 용병(이종 외부AI)으로 교차 검증 후 채택.
  • 제약 — Max·Team·Enterprise 플랜 한정(Pro 미지원), "고비용 특수부대" 원칙으로 신중 투입.

6.2 DW 단독 대비 백호 특허+DW의 우월점

DW 단독 약점백호 특허+DW 해결 방법
동종 검증 편향 용병 이종 교차 검증으로 보완
인간 게이트 부재 소대장 승인 3회 게이트 유지
소대장 컨텍스트 집중 DW 부대장이 별도 진지에서 포격 전담
복합 도메인 처리 한계 보병 분대(Alpha, Bravo, Charlie 등 NATO 분대)가 전문성 분산 처리
한 줄 요약: 백호 특허는 "어떻게 싸울 것인가"의 작전 골격이고, DW는 "포병 화력"이다. 백호 특허 안에 DW가 포병 부대로 배속되면서 두 기술의 약점이 상호 보완된다.
